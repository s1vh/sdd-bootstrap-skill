# SDD Bootstrap — experimental v0.2 (Portfoling feedback)

This document is for the **Skill distribution repository**, not for projects generated by the Skill. The installable artifact remains `sdd-bootstrap/`.

## Scope

The experimental candidate implements four coordinated improvements:

1. **Optional Git initialization:** project-files ZIP without `.git/` by default; stack-specific `.gitignore` always; one-time check when Git subsequently appears.
2. **Truthful agent provenance:** stable unique project-agent identity; independent, optional verified model/platform; precise `Co-authored-by` format; no copying identity from previous agents or borrowing a human/platform email without justification.
3. **Agent-autonomous development integration:** history-preserving non-squash topic→`dev` merge, safe branch deletion after verification, cheap routine checks. Stable `main` promotion remains explicitly human-controlled; **no deployment from `dev` or topic branches**; special gameplay-test gate remains.
4. **Critical-path-first hosting decisions:** distinguish immediate pilot from future commercial horizon; veto hard constraints before scoring providers, check exact plan limits/cost exposure/commercial use and actual essential user journeys. Define early authorized feasibility spikes for unknown blockers.

Full source discussion: `01`–`04` improvement review Markdown files in the accompanying update ZIP; they are **not required at runtime**.

## Pilot validation

Install **the explicit `experimental` branch** in a test environment by cloning that branch and pointing the agent's Skill loader to `sdd-bootstrap/`. Do **not** assume the normal installation instructions, which default to `main`, install this candidate.

```bash

git clone --branch experimental --single-branch https://github.com/s1vh/sdd-bootstrap-skill.git sdd-bootstrap-skill-exp
```

The `experimental` branch must already exist and contain the candidate before this command will work. This README **does not claim that branch has been created or pushed**.

### Behavioral tests (human review and actual agent sessions required)

1. **Minimal static prototype** — request a bootstrap with no Git; ensure output `.gitignore` exists but `.git/` is absent. Initialize Git in a later coding-agent session and verify ignore protection survives.
2. **Multi-agent handoff** — agents receive previous commit with a plausible model version, but their own runtime model is not disclosed. Check that they use project-local agent identity without guessing model or platform, and that the coauthor trailer has honest metadata.
3. **Feature completion** — assign two bounded tasks. Confirm agent can create commits and non-squash topic→`dev` merges, retain original SHAs and contributors, and safely retire integrated branches without asking for each merge. Confirm no independent `dev`→`main` merge, history rewrite or deployment.
4. **Pilot hosting failure trap** — require zero **charge exposure** and Google login in a small pilot, while preferring later commercial hosting continuity. Verify the agent checks plan-specific CPU/runtime/quotas, cost and terms before selection, and defines a scoped early feasibility spike if OAuth remains unproven.
5. **Non-web project counterexample** — request a small offline game, library or utility. Check that hosting and agent registries are not unnecessarily imposed.

For each exercise record: input context, sources considered, questions asked, exact output assertions, any inaccurate certainty, and human-observed outcome. The unit tests above do **not** execute these behavioral cases.

## Promotion criterion

Review both normative files, execute static checks and selected cross-provider behavioral tests, reconcile any interaction with existing Skill `README.md`, and only **then** authorize integrating `experimental` into `main`. `main` remains the installation/default distribution branch. No automatic push, merge or deployment is authorized by this document.
